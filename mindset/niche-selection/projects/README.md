# Project notes

The core skill (`../SKILL.md`) is generic. A project note adds what the method cannot know: the
owner's existing sites and apps, their audiences, what the owner knows well, and which links between
sites would genuinely help readers.

## How project notes work

1. Before scoring niches for a specific owner or portfolio, check this folder for `<name>.md`. If it
   exists, load it after `SKILL.md`.
2. The note informs the optional columns on the scoring sheet (fit with existing sites, owner
   knowledge, safe automation share) and the linking plan. It never changes the four tests or the
   decision rules.
3. Facts must be verifiable (live sites, real analytics, the owner). Mark anything unconfirmed
   `[confirm]`.
4. Keep each note short (about 300–500 words) and current.

## Template

```markdown
# <Owner or portfolio> — niche selection notes

## Existing sites and apps
One line each: name, URL, audience, main traffic source, how it earns.

## Strengths
Subjects the owner knows first-hand, languages, local access, data or contacts others lack.

## Linking options
Which existing site would a new site's readers genuinely need next, and for what.

## Constraints
Daily time available for review, budget, topics to avoid, legal or brand limits.

## Past decisions
Niches already scored, the date, the result and why.
```
